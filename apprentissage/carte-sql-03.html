Classer

facile

Je veux un rang sans perdre de lignes.

J'écris
  • ROW_NUMBER() OVER→numéroter
  • PARTITION BY→recommencer par groupe
Exemple 
SELECT nom,
  ROW_NUMBER() OVER (
    PARTITION BY pays
    ORDER BY score DESC)
FROM clients;

Tips : pour garder seulement le n° 1, passez par une CTE (WITH).

Cumuler

facile

Je veux la valeur précédente ou un total qui s'additionne.

J'écris
  • LAG / LEAD→ligne d'avant, d'après
  • SUM() OVER→total cumulé
Exemple 
SELECT date_cmd,
  SUM(montant) OVER (
    ORDER BY date_cmd
    ROWS UNBOUNDED PRECEDING)
FROM commandes;

Tips : écrivez ROWS pour un cumul ligne à ligne : le défaut est RANGE.

Gérer les NULL

moyen

Je veux des résultats justes malgré les valeurs manquantes.

J'écris
  • IS DISTINCT FROM→comparer, NULL compris
  • NULLIF(x, 0)→éviter la division par zéro
Exemple 
SELECT total / NULLIF(nb, 0)
FROM stats;

Tips : x NOT IN (1, 2, NULL) n'est jamais vrai : aucune ligne ne sort.

Valider du texte

moyen

Je veux savoir si un texte peut devenir un nombre ou une date.

J'écris
  • pg_input_is_valid→la conversion marchera-t-elle ?
  • ~ 'motif'→tester un format (regex)
Exemple 
SELECT pg_input_is_valid(
  '2026-02-30', 'date');
-- false

Tips : une regex vérifie le format, pas la valeur : '2026-02-30' passe.

Écrire en sécurité

avancé

Je veux pouvoir tout annuler si ça se passe mal.

J'écris
  • BEGIN … COMMIT→valider en bloc
  • ROLLBACK→tout annuler
Exemple 
BEGIN;
UPDATE comptes
  SET solde = solde - 100
  WHERE id = 1;
ROLLBACK;

Tips : tant que COMMIT n'est pas lancé, rien n'est enregistré.

Aller plus loin
SAVEPOINT ON CONFLICT DO UPDATE RETURNING

Accélérer

avancé

Je veux des requêtes rapides et des accès contrôlés.

J'écris
  • CREATE INDEX→accélérer une recherche
  • EXPLAIN ANALYZE→voir comment la requête s'exécute
Exemple 
CREATE INDEX idx_cmd_client
ON commandes (client_id);

Tips : EXPLAIN ANALYZE exécute vraiment la requête, même un DELETE.

Aller plus loin
CREATE SCHEMA IDENTITY GRANT REVOKE

Où se calcule une fenêtre : FROM → WHERE → GROUP BY → HAVING → OVER (…) → ORDER BY → LIMIT
Conséquence : on ne filtre pas un ROW_NUMBER() dans le WHERE : on passe par une CTE
