Les commandes Linux utiles en Data Engineering

Les pipelines de données tournent presque tous sur des serveurs Linux. Avant d'ouvrir Python ou Spark, quelques commandes suffisent souvent pour comprendre un fichier, retrouver une erreur ou automatiser un traitement.

24 octobre 2026 · lecture 4 min

1. Explorer un fichier sans l'ouvrir

Un fichier CSV de plusieurs gigaoctets ne s'ouvre pas dans un tableur. Ces commandes lisent seulement ce qu'il faut.

head -n 5 ventes.csv        # les 5 premières lignes (et l'en-tête)
tail -n 5 ventes.csv        # les 5 dernières
wc -l ventes.csv            # le nombre de lignes
du -sh data/                # la taille d'un dossier
less ventes.csv             # parcourir le fichier page par page

Un réflexe utile : comparer wc -l sur le fichier source et sur le fichier chargé, pour vérifier qu'aucune ligne n'a été perdue en route.

2. Filtrer et compter

Les commandes se combinent avec le symbole | (le pipe) : la sortie de l'une devient l'entrée de la suivante.

grep "ERROR" pipeline.log                  # les lignes qui contiennent ERROR
grep -c "ERROR" pipeline.log               # combien il y en a
cut -d',' -f3 ventes.csv | sort | uniq -c  # nombre de lignes par valeur de la 3e colonne
awk -F',' '$4 > 1000' ventes.csv           # les lignes dont la 4e colonne dépasse 1000

La troisième ligne est un vrai petit contrôle qualité : elle montre en une seconde si une colonne contient des valeurs inattendues.

3. Suivre un traitement en direct

tail -f pipeline.log        # afficher les nouvelles lignes au fil de l'eau
ps aux | grep python        # retrouver un script en cours d'exécution
top                         # voir la mémoire et le processeur utilisés
nohup python job.py &       # lancer un script qui continue après la déconnexion

4. Récupérer et déplacer des données

curl -O https://exemple.org/donnees.csv     # télécharger un fichier
gzip donnees.csv                            # compresser
zcat donnees.csv.gz | head                  # lire un fichier compressé sans le décompresser
rsync -av data/ serveur:/backup/data/       # copier en ne transférant que ce qui a changé

5. Planifier un traitement

Avant les orchestrateurs comme Airflow, il y a cron, qui lance une commande à heure fixe. Une ligne dans crontab -e suffit :

# tous les jours à 6 h, lancer l'ingestion et garder la trace dans un log
0 6 * * * python /opt/pipeline/ingestion.py >> /var/log/ingestion.log 2>&1

cron ne gère ni les dépendances entre tâches, ni les relances en cas d'échec : c'est précisément ce qu'apportent les orchestrateurs.
