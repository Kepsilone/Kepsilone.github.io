Fabric · KQL

Interroger des données en continu avec KQL dans Microsoft Fabric

KQL (Kusto Query Language) est le langage de requête des données temps réel dans Microsoft Fabric. Il est conçu pour les journaux, la télémétrie et les mesures de capteurs : des millions de lignes horodatées qu'on veut filtrer et agréger en quelques secondes.

Par Sabeur JEDID · 24 octobre 2026 · lecture 5 min

Où se trouve KQL dans Fabric

KQL fait partie de l'expérience Real-Time Intelligence de Fabric :

  • un Eventstream reçoit les événements en continu et les envoie vers une base ;
  • un Eventhouse contient une ou plusieurs bases KQL, optimisées pour les données horodatées ;
  • un KQL Queryset sert à écrire et enregistrer les requêtes ;
  • un Real-Time Dashboard affiche les résultats en direct.

Une syntaxe en pipeline

Une requête KQL part d'une table, puis enchaîne des opérations séparées par |, comme les commandes Linux. Chaque étape reçoit le résultat de la précédente. Les exemples suivants utilisent une table Mesures de capteurs industriels, avec les colonnes Timestamp, Machine, Capteur et Valeur.

Mesures
| where Timestamp > ago(1h)           // la dernière heure
| where Machine == "M01"              // une seule machine
| project Timestamp, Capteur, Valeur  // les colonnes utiles
| take 10                             // un aperçu de 10 lignes

Agréger

summarize joue le rôle du GROUP BY en SQL :

Mesures
| where Timestamp > ago(1d)
| summarize Moyenne = avg(Valeur), Maximum = max(Valeur), Nombre = count() by Machine
| order by Maximum desc

Découper le temps et tracer une courbe

La fonction bin() regroupe les mesures par tranches de temps, ici 5 minutes, et render affiche directement le graphique :

Mesures
| where Timestamp > ago(1d) and Capteur == "Temperature"
| summarize Moyenne = avg(Valeur) by bin(Timestamp, 5m), Machine
| render timechart

Repérer des anomalies

KQL sait construire des séries temporelles et y chercher des valeurs anormales, sans écrire de modèle :

Mesures
| where Capteur == "Temperature"
| make-series Moyenne = avg(Valeur) default = 0
    on Timestamp from ago(1d) to now() step 5m by Machine
| extend Anomalies = series_decompose_anomalies(Moyenne)
| render anomalychart with (anomalycolumns = Anomalies)

series_decompose_anomalies sépare la tendance et la saisonnalité de la série, puis signale les points qui s'en écartent trop.

Les équivalences avec SQL

  • SELECT colonnes → project
  • WHERE → where
  • GROUP BY → summarize … by
  • ORDER BY → order by (ou sort by)
  • LIMIT / TOP → take / top
  • colonne calculée → extend

La différence principale : en KQL, on lit la requête dans l'ordre où elle s'exécute, de haut en bas.
